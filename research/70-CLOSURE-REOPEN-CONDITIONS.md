## HDF reopen condition

Reopen an existing HDF only for a concrete Host-relevant counterexample that names an exact frozen claim/truth-condition and demonstrates that it fails.

The following do **not** reopen a Foundation:

- importance or recurrence of a concept;
- a new product/API/schema/class/test shape;
- implementation convenience;
- compatibility pressure;
- a new consumer using the Host proper noun;
- a desire for a more symmetric architecture;
- a directory/navigation gap;
- product growth by itself.

## Primitive Host / Generic Coordination owner reopen condition

A stronger owner hypothesis may reopen only if evidence shows all of the following:

1. materially different real consumers reproduce the same relation responsibility;
2. the responsibility is non-bypassable and irreducible rather than a shared vocabulary convenience;
3. source-owner and consumer-local solutions measurably fail;
4. the surviving truth-maker cannot be reduced to existing Host, Harness, Runtime, Normative, World, Network, Human, Finance, or relevant domain contracts;
5. the candidate does not become a global truth graph, scheduler, consensus substrate, authority oracle, mirrored source database, or universal maintenance owner.

Until that burden is met, Generic Coordination remains closed.
